# Provider contracts

| Provider | Verified contract and fields |
| --- | --- |
| [LP Agent OpenAPI](https://github.com/lpagent/docs/blob/main/api-reference/openapi.json) | Base `https://api.lpagent.io/open-api/v1`, `x-api-key`, `chain=SOL&platform=meteora`. Pool `top-lpers` returns `data[].owner`, `protocol`, `chain`, and `pagination.hasNextPage`, with `page`/`limit` and documented `total_pnl_native` sort. LP Agent [lists this route as Premium/Enterprise](https://portal.lpagent.io/dashboard/). Owner `/lp-positions/open` returns a flat data array. `/lp-positions/historical` uses `pageSize` and nested `data.data` and `data.pagination.totalPages`. Position ID is `tokenId`, bounds use `tickLower`/`tickUpper`, timestamps use `createdAt` and `closeAt` or `close_At`. SOL uses `inputNative`, `outputNative`, `collectedFeeNative` and `pnl.valueNative` (or `pnlNative`). The history scan filters by close date after pagination because the documentation gives no timestamp semantics for `from_date`. |
| [Meteora DLMM production OpenAPI](https://dlmm.datapi.meteora.ag/swagger-ui/) | `/pools` returns `data/pages` and accepts `page/page_size/sort_by/filter_by`. `/pools/{address}` returns the pool object. Verified against a public pool-list response that `created_at` uses ms and volume has no 5m field. The last completed 5m candle comes from `/pools/{address}/volume/history`; its timestamp is normalized to ms. Pool stats use `token_x/token_y`, `tvl`, `fees`, `volume` and `pool_config.bin_step`. Short-window fees/TVL and the simple annualized fee estimate are derived. |
| Meteora PnL and history | `/positions/{pool}/pnl?user=…&status=closed` returns `positions`, `hasNext`, `positionAddress`, `isClosed`, `closedAt` (Unix seconds), and optional `pnlSol`. Cross-check joins by position address and close time within 60 seconds, requires 80% coverage and compares same-position sums with a default tolerance of 25% or 0.5 SOL, whichever is greater. Meteora documents current SOL price for some conversions. Check differences in valuation date, gas, fees and rewards with production samples. `/positions/{position}/historical?event_type=add&order_direction=asc` supplies the first add signature for historical strategy lookup. |
| [Jupiter Price V3](https://developers.jup.ag/docs/api-reference/price) and [Tokens V2](https://developers.jup.ag/docs/api-reference/tokens/search) | `GET https://api.jup.ag/price/v3?ids=…` returns `[mint].usdPrice`; `GET /tokens/v2/search?query=…` returns token `id`, `totalSupply`, `organicScore` and optional audit flags. FDV uses price × total supply. Missing quotes stay unknown. For non-SOL pairs, the first pool mint is shown as Coin CA and the range is token Y per token X. Jupiter audit flags and Meteora pool flags provide partial risk context. |
| [Helius webhooks](https://www.helius.dev/docs/webhooks) and [update contract](https://www.helius.dev/docs/api-reference/webhooks/update-webhook) | Enhanced payload is an array with `signature` and `transactionError`. Helius documents retries and duplicate delivery. Management uses Bearer authentication with `https://api-mainnet.helius-rpc.com/v0/webhooks/{id}`. The configured webhook ID is updated with address list, HTTPS URL, `ANY`, type `enhanced` and the verbatim inbound Authorization header. Status is checked every 15 minutes. Read the canonical successful transaction through Solana `getTransaction` at confirmed commitment. |
| [Solana RPC](https://solana.com/docs/rpc) | `getTransaction` with `jsonParsed` and v0 support supplies outer instructions, parsed inner transfers, stack height where available and pre/post token balances. `getAccountInfo` verifies the position owner for add-only transactions. Fallback uses one `logsSubscribe` per tracked address and `getSignaturesForAddress` on reconnect. |
| [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage) | `sendMessage` only. The keyboard uses `copy_text` and URL buttons. Scanner continues to own polling. |

LP Agent requests default to 10 RPM and Jupiter uses conservative keyed/keyless limits. Meteora is locally capped at 4 requests/s. RPC has separate 6/s realtime and 3/s background lanes. Rate limits, budgets, and coverage should be checked against the actual provider plan before enabling alert delivery.

Live LP Agent entitlement, actual owner history and PnL coverage, Jupiter enrichment and Helius delivery are release checks requiring configured credentials. The mock uses recorded fixture inputs and a deterministic dataset rather than live accounts. Optional RugCheck is omitted because Jupiter and Meteora supply the initial risk flags.
